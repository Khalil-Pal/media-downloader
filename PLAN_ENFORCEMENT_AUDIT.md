# Plan Enforcement Audit

## Audit Result

Before this change, plan enforcement was not wired into downloads or
conversions.

- `user_has_active_plan()` existed in `services/payments.py`.
- Neither `handlers/downloader_handler.py` nor
  `handlers/convert_handler.py` called it.
- No download or conversion path read `plan`, `plan_expires_at`, plan
  capabilities, or package balances.
- As a result, free, expired, and paid users all reached the same media and
  conversion logic. The payment/plan code was infrastructure only.

## Enforced Rules

The implementation now follows the limits already advertised in the bot:

| User state | Download access | Conversion access | File limit |
| --- | --- | --- | --- |
| Free | 10 successful downloads per UTC day | 3 successful conversions per UTC day | 500 MB plan cap |
| Downloader Pro | Unlimited | Not included | 2 GB |
| Converter Pro | Not included | Unlimited | 2 GB |
| All-in-One / Annual | Unlimited | Unlimited | 2 GB |
| Usage packages | Shared download-or-conversion balance | Shared download-or-conversion balance | Catalog value |
| Admin (`ADMIN_ID`) | Bypass | Bypass | Existing system limits still apply |

Only successful Telegram deliveries consume usage. Existing global rate and
file-size limits continue to apply in addition to plan limits.

Free counters use the existing `user_plans` table as a `free_daily` row and
reset at UTC midnight. No table or column was added. The project's existing
in-memory DB fallback uses the same behavior when PostgreSQL is unavailable.

The existing lazy expiry function remains authoritative. On the first request
after expiry, the user receives the specific expired-plan message and the
`users` row is downgraded to `free`.

The Free Plan's displayed two-day duration was not made into a lifetime cutoff.
This implementation uses the daily quotas as the free-tier definition requested
by this audit.

## Covered Entry Points

| Entry point | Enforcement |
| --- | --- |
| `/download <url>` | Preflight before quality picker; authoritative check in `_run_download()` |
| `/audio <url>` | Authoritative check in `_run_download()` |
| Pasted media URL | Preflight before quality picker; authoritative callback check |
| Quality callback | Calls the gated `_run_download()` |
| Uploaded conversion file | Check before target picker |
| Conversion callback | Rechecks before rate limiting and conversion |

The callback checks prevent an old keyboard from bypassing a limit reached
after the keyboard was created.

## Files Changed

- `services/payments.py`: centralized entitlement decisions, expiry handling,
  free quotas, paid capabilities, file limits, admin bypass, and usage
  recording.
- `services/db.py`: atomic free and package counter updates using the existing
  `user_plans` table.
- `handlers/downloader_handler.py`: download preflight/execution gates and
  successful-use accounting.
- `handlers/convert_handler.py`: conversion upload/callback gates and
  successful-use accounting.
- `handlers/menu.py`: keeps persisted free counter rows displayed as the Free
  Plan.
- `en.json`, `ar.json`, `ru.json`: translated rejection and upgrade messages.
- `tests/test_plan_enforcement.py`: handler, entitlement, counter, expiry,
  capability, package, callback, locale, file-size, and admin tests.

The `/upgrade`, `/approve`, `/reject`, payment-proof, downloader, converter,
cookie, and Telethon implementations were not otherwise changed.

Additional passing tests confirm:

- Downloader Pro cannot convert.
- Converter Pro cannot download.
- Usage packages decrement one shared credit atomically.
- Free counters reset on a new UTC day.
- Stale conversion callbacks cannot bypass a newly reached limit.
- Admin remains allowed after both free counters are exhausted.
- Every rejection key exists and points to `/upgrade` in English, Arabic, and
  Russian.
